# workflow — 60분 진행 방식

## 시작 (과제 받은 직후)

1. `./setup.sh` 실행 (환경 생성)
2. 과제 문서를 읽고 `CLAUDE.md` 작성 (첫 줄 `@AGENTS.md`)
   ```md
   @AGENTS.md

   # 과제 요구사항
   - [ ] 필수:
   - [ ] 선택:

   # 데이터 모델

   # API 명세
   | Method | Path | 요청 | 응답 | 에러 |
   |---|---|---|---|---|
   ```
3. 과제가 기본 규칙과 다르면 해당 `docs/*.md`만 몇 줄 수정
4. Claude Code 시작

## 시간 배분

| 시간 | 단계 | 산출물 |
|---|---|---|
| 0–10분 | 요구사항을 필수/선택으로 분리, 데이터 모델·API 명세 작성 | `CLAUDE.md` |
| 10–35분 | 필수 기능을 기능 단위로 구현 (백엔드 → 프론트) | 기능별 커밋 |
| 35–50분 | 선택 기능, 에러 처리, 입력 검증 | 기능별 커밋 |
| 50–60분 | `/verify`, README 작성, 시연 흐름 점검 | `README.md` |

- 40분 시점에 필수 기능이 안 끝났으면 **선택 기능은 포기**한다.
- 한 문제에 5분 이상 막히면 범위를 줄이거나 더 단순한 방법으로 우회한다.
- 진행 상황은 `CLAUDE.md`의 요구사항 체크박스로 관리한다.

## 기능 하나의 흐름 (병렬 테스트)

1. 메인 에이전트: API 구현 → Swagger에서 1회 확인
2. `test-writer`를 **백그라운드로** 호출: "기능 A 테스트 작성·실행 (엔드포인트: ...)"
3. 메인 에이전트는 기다리지 않고 기능 A의 화면 또는 기능 B를 진행
4. `test-writer` 결과 도착
   - 통과 → 커밋 (`feat: ...`, `test: ...`)
   - 실패 → 명세 위반이면 구현 수정 / 테스트가 명세를 잘못 해석했으면 사용자에게 보고
5. 다음 기능에서 반복
